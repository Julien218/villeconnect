# Base44 development notes

- `docker compose -f docker-compose.base44.yml up -d --build` starts Expo web on 3000, the API on 8000 and MySQL. Source is bind-mounted; Metro and TypeScript/Node watch live changes. Do not use CI=true for Metro: it disables its file watcher.
- Expo 57 enables the standalone desktop React Native debugger by default, which fails on missing GTK libraries in the headless Node container. Set `EXPO_UNSTABLE_HEADLESS=1` for web development; this disables desktop debugger installation without disabling Metro's watcher (unlike `CI=true`).
- The Expo 57 dev server checks Origin, including font requests. Base44's upstream Host differs from the public browser Origin. `macommune-app/app.config.js` sets `extra.router.origin` from `EXPO_PUBLIC_WEB_APP_URL` only in development. A working HTML response alone does NOT prove fonts/app rendering work: test an `/assets/` request with the public Origin too. No resolved sandbox hostname belongs in source.
- Repo migrations start at 007. `.base44/legacy-schema.sql` supplies empty development-only baseline tables inferred from the existing API queries; it is not a recovered production schema. `.base44/migrate.sh` applies forward migrations once (never `_ROLLBACK.sql`). Local MySQL data persists in a named volume. No remote data or production credentials are needed for preview.
- API and web use separate origins and the existing bearer-token auth, not cookies. The API CORS list includes the dynamic preview origin. Platform secrets are the last/only API env_file; do not override JWT_SECRET, WALLET_QR_SECRET or CITY_HASH_SALT in compose environment.
- RESEND_API_KEY is optional for boot but required for actual verification/reset email delivery. No development email bypass is provided.
- Checks: `docker compose -f docker-compose.base44.yml exec -T web npx tsc --noEmit`; `docker compose -f docker-compose.base44.yml exec -T api npm run validate`; `curl http://localhost:8000/health`. Confirm `/` serves the live Expo `entry.bundle?platform=web&dev=true` bundle, not a static export.
- Home's night design lives in `components/home/`; the real wallet/dashboard API loading remains in `app/(tabs)/index.tsx`. The guest city remains the existing Dour pilot from branding. Weather and fallback event examples are explicitly illustrative, never seeded as real events. Unimplemented messaging, AI, alerts and reports show honest information dialogs. Existing agenda, directory, wallet, services and profile remain reachable.
- Fuel proximity: `use-fuel-location.ts` requests a foreground position on entering `/fuel`, with bounded wait and retry; no background tracking or coordinate persistence in app state storage. `fuel.getStations` accepts paired latitude/longitude and a 1–50 km radius, filters geocoded stations in SQL before price ordering/limit, and retains postal-code compatibility for older clients. CARBU.COM is NOT connected: the existing `fuel_stations` table remains the sole price source; do not seed invented prices. Native builds must be rebuilt for the new expo-location permission plugin. Checks include `server/test/fuel.test.js`; database distance/ordering can be checked using an isolated temporary table, never by publishing fake stations.
- `night-*.webp` assets are cropped artwork from the user's supplied mockup, not full-screen screenshot overlays. Text, navigation, hexagonal buttons, pagination and event cards are live components.
- Navigation transitions are centralized in `macommune-app/components/screen-transition.tsx`: tabs interpolate navigator progress (fade, short lateral shift, depth); native Stack uses `fade_from_bottom`, while its web fallback animates focus without remounting screens. Both layouts honor reduced motion. Use Expo Router's bundled navigation types/hooks (SDK 57), not the separate `@react-navigation/native` context.
- App buttons import the aliased wrappers in `components/neon-button.tsx`; these preserve original props and handlers and add theme-aware bevels, shadows, disabled treatment and reduced-motion-aware press depth. `neonSurface={false}` is for image/SVG-shaped buttons with their own relief (home hexagons use layered SVG paths), not ordinary buttons. Modal backdrops remain raw touchables. No global DOM/CSS patching is needed.
